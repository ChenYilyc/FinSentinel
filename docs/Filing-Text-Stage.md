# 公告文本导入与原文定位

## 用三分钟验收

启动后端并打开 `http://127.0.0.1:8000/#agent`，选择 Local 模式。在 Filing extract 中选择 `examples/filing-demo.txt`。这是一份故意使用虚构营收的测试材料。

| 操作 | 预期结果 |
| --- | --- |
| 填 NVDA、2025-Q3、发布日期 2025-11-12。截止日也填 2025-11-12，Text contains 填 125，然后运行 | 一条公告命中，View line 3 打开全文，第 3 行高亮，包含 USD 125 million；下方 NVDA 敞口取自本次持仓 |
| 只将截止日改为 2025-11-11，重新运行 | 公告检索为空。模拟持仓估值仍有独立日期 |
| 截止日恢复到 2025-11-12，关键词改为 Revenue | 命中第 3、4 行，分别是本季度和对照季度营收 |
| 点 Use sample excerpts，再另选 AMD、2025-Q3，清空关键词并运行 | 恢复内置 AMD 数据集及对外原文链接 |

也可使用自己的 UTF-8 文本摘录，每次附一份文件，每行放一段便于引用的原文。公司、财季和发布日期为导入者提供的信息。每个请求自带文件内容，刷新页面后重新选择。Live 模式会将问题、文件标签以及工具按需取得的摘录或持仓结果发送给配置的模型服务。文件名保留在页面上。PDF、OCR、持久文档库和语义检索仍属于后续验收项。

## 从一个错误读懂三处代码

以示例第 3 行的 125 和第 4 行的 100 为例。两个数都能在文档中找到，但把对照季度的数字引用为本季度营收，会导致答案错误。

1. 在 `backend/filing_text.py` 看 `passages()`。它先按物理行编号，再跳过空行。若把过滤空行放在编号之前，源文件里的第 3 行就会被标成第 2 行。行定位符包含规范化文本的 SHA-256 摘要，换行格式从 CRLF 改成 LF 可以继续比较，金额被修改后则产生新的版本标识。
2. 在 `backend/agent_tools.py` 看 `search_filings()`。当请求带有文件，只搜索该文件。公司、财季、发布日期与关键词共同决定召回结果。关键词进行大小写无关的字面匹配，每次最多返回前 5 条，同时返回命中总数。检索为空时保留空结果，避免用内置摘录填充空缺。
3. 在 `tests/test_filing_text.py` 看 `test_live_citation_must_reference_returned_line`。让工具只取第 3 行，同时模拟模型提交一条正确引文和一条改成第 4 行的引文。前者通过，后者返回 `source_not_retrieved`。如果模型逐字引用第 4 行却在解释中把比较期说成本季度，仍需另行判断解释是否成立。

运行 `python -m unittest discover -s tests -p test_filing_text.py -v` 可重现本阶段五项测试。输入限制为 48 KiB、最多 1000 行、单行最多 1200 字符。超限会提示调整摘录。
