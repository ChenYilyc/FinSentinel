# FinSentinel 技术方案与分阶段验收标准

**版本** v1.0　｜　**基准日期** 2026-11-18　｜　**适用范围** 新加坡金融 AI 实习求职展示版

**交付目标**　让投资者或客户经理导入一份持仓，读懂一份新公告与哪些持仓有关，看到可复算的组合风险，并在订阅条件满足时收到一次可追溯的站内提醒。另设一个可独立评估的市场方向预测实验。面试演示使用模拟客户持仓，行情和公告可使用有来源、有时间戳的真实数据。

**如何使用本文**　六个开发阶段及主要选型沿用已讨论方案。下文的工作量、样本数量和通过阈值是本版提出的验收基准。每项完成后勾选，在末尾记录日期、代码版本和证据。若范围或阈值变化，保留旧值、修改理由及新版本号，再按新版验收。

## 1　当前交付边界

| 项目 | 第一阶段已实现 | 如何复核 |
|---|---|---|
| 持仓导入 | 接收 ticker、quantity、currency 三列，支持资产清单内的美元多头与现金，合并重复代码 | 用 `examples/portfolio.csv` 导入六项持仓，再用未知代码检验报错 |
| 估值及集中度 | 按数量 × 固定单价估值，含现金计算总权重。行业权重严格超过阈值才提醒，现金免于集中度提醒 | 总市值应为 100,000 美元，半导体占 42%。阈值 35% 时有一条提醒，42% 时为零 |
| 压力与历史风险 | 指定行业同时下跌，其余价格固定。用相同数量回看六个模拟收盘日，计算期间收益、日收益样本标准差、最大回撤 | 半导体下跌 8% 的组合损失为 3,360 美元。参考序列从 100,700 降至 96,700 美元，最大回撤约 3.97% |
| 工程状态 | React 页面、FastAPI 接口、计算模块及 Compose 配置已交付。7 个计算测试通过；已完成前端构建与进程内接口检查 | 项目根目录运行 `python -m unittest discover -s tests -v`。尚待在本机浏览器和运行中的 Docker 引擎完成操作验收 |

**数字的含义**　股票代码对应真实标的；默认数量、价格和六日轨迹来自示例文件。用户现在可以上传符合格式的自有数量，但页面仍按模拟价格估值。35% 是提醒阈值，8% 是假设跌幅。两者由用户设定。这里的六日表现描述“今天这组数量如果一直持有”的结果；复原账户实际收益还需要历史成交、现金流和公司行动记录。

## 2　从模拟输入切换到真实数据

| 数据 | 目标来源与接入方式 | 切换成功的证据 |
|---|---|---|
| 持仓与现金 | 用户授权导出的券商 CSV，映射资产代码、数量、币种、快照时间。展示账户可继续用模拟数量 | 导入对账后的数量与现金；未知资产、非 USD、空数量逐行提示。报告分别标注持仓来源和行情来源 |
| 日频行情及资产清单 | 从获准使用的行情 API 或授权历史文件取得收盘价、成交量、交易日、币种和公司行动。独立维护代码、交易所及行业映射 | 抽查两只股票及预测 ETF 的三个交易日，对照原始记录验证日期、价格和币种。保留供应商、抓取时间和数据版本 |
| 公告、财报与新闻 | 优先接入 SEC EDGAR、公司投资者关系网页及用户上传的 PDF 或文本。新闻按来源许可接入 | 从事件点回原文。PDF 对应页码，HTML 或文本对应章节、段落或原句；保留原始链接、发布时间、抓取时间及文档版本 |
| 情景与预测 | 行业下跌幅度和集中度阈值保留为可编辑设置。训练和评估使用真实历史数据，随后逐日保存预测并在五个交易日后结算 | 页面分别标注“已观测行情”“假设情景”“模型预测”。预测记录包含预测时点、数据截点、模型版本和到期标签 |

**工程改动。** 当前风险模块在加载时读取 `examples/universe.csv` 及 `examples/prior_closes.csv`。下一步让估值函数接收同一接口提供的带时点行情快照，分别实现固定样例读取器和真实数据读取器。保留固定样例，确保更换供应商后，100,000 美元参考组合仍能重复验算。日频读取器在美股交易日收盘且供应商完成更新后运行，使用美东交易日识别假日和夏令时，统一保存带时区的时间戳。

**数据质量门槛。** 当前估值使用相同交易日的可比收盘价；收益序列声明拆股、分红和复权口径，当前数量跨拆股回放时保持单位一致。缺价、公司行动口径不明或资产映射失败时，显示受影响资产和最近有效日期，暂停依赖这些数据的指标及提醒。缓存保留来源标记。真实模式不得悄悄读入模拟价。

**数据源决策。** SEC EDGAR 提供公司申报记录和 XBRL 财务事实；市场交易价格另选供应商。Alpha Vantage 可作为日线候选，其每日复权接口列为付费功能。选定前确认历史覆盖、公司行动、限额、公开展示与再分发权限，记录核对日期及适用套餐。若只获得内部分析授权，公开演示使用模拟行情，真实数据验收在获准环境完成。[SEC 官方接口](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) · [Alpha Vantage 官方文档](https://www.alphavantage.co/documentation/#dailyadj)

## 3　技术栈与模块职责

| 模块 | 已选技术 | 职责及当前状态 |
|---|---|---|
| 前端与 API | React、TypeScript、Vite；Python、FastAPI、Pydantic | 已有持仓导入、参数校验、风险面板；后续增加任务进度、原文引用和提醒中心 |
| 数据与身份 | Supabase Auth、PostgreSQL、pgvector、Storage | 待接入。保存用户持仓、文件、文档块、事件、行情快照及分析记录；按用户限制数据访问 |
| 文档与检索 | Docling、结构化事件 Schema、Embedding、PostgreSQL 全文检索、向量检索、重排序 | 待接入。按公司和时间筛选，分别做词项及语义检索，合并排序后回传原文位置。扫描件或复杂表格按需 OCR 或视觉识别 |
| Agent 与工具 | LangGraph 单主 Agent、Postgres 检查点、云端 LLM API | 待接入。Agent 根据证据选择检索、补查或调用风险工具；Python 负责数值，报告保留调用参数、快照和引用 |
| 预测实验 | pandas、scikit-learn、LightGBM | 待开发。比较历史上涨频率、动量规则、逻辑回归和 LightGBM；在相同时间切分上评估加入文本特征的增量 |
| 后台任务 | Celery、Redis、独立 Worker、单实例定时调度器 | 待接入。处理解析、每日拉取和订阅提醒；记录幂等键、重试和送达结果 |
| 工程与部署 | uv、Docker Compose、Vercel、AWS、Supabase | 已有本地配置；公网部署待验收。LLM 与 Embedding 型号经样本对比后记录版本，变更 Embedding 时重建索引 |

**扩展范围。** Chronos-2 等时间序列基础模型、MCP 工具服务、关系图、多 Agent、Temporal、邮件提醒和新加坡市场，均需单独说明预期收益并另排期。第一版覆盖 10–20 个美股标的、美元日频数据、一个宽基 ETF 五日预测目标及站内提醒。

## 4　预计部署方式

| 位置 | 运行内容 | 运维与验收重点 |
|---|---|---|
| 本地 Windows | FastAPI 提供 API 及已构建的 React 页面；开发时使用 Vite。Compose 随阶段增加依赖服务 | 在新环境按 README 启动，跑通示例。固定样例测试不依赖外部行情或模型密钥 |
| Vercel | 构建并托管 React 静态前端 | 设置公网 API 地址和允许的前端来源，用 HTTPS 验证登录、上传、任务状态和报告 |
| AWS 新加坡区域 | 首版以单台 Lightsail 主机运行 FastAPI、Redis、Celery Worker 和一个调度器 | 提交长任务返回任务 ID；关闭页面后继续处理。设置私有队列、任务超时与重试，记录 CPU、内存及 OCR 峰值 |
| Supabase 及模型服务 | 优先同区域的 Auth、Postgres、pgvector 和私有文件存储；Worker 按需调用模型 API | 用户级访问隔离、短时文件链接、后端保管服务密钥；日志中记录版本、耗时及成本，避免写入原始持仓与密钥 |

**一次公网演示的路径。** 用户通过 Vercel 页面登录并发起分析，FastAPI 校验身份和文件归属后创建任务。Worker 从队列取任务，读取私有文档，检索证据并调用风险工具，持久化结果。用户凭任务 ID 查看自己的报告。每日调度复用这些工具，满足已订阅阈值时写入站内提醒。单主机展示版需保留数据库备份和可恢复的任务记录。云端资源、供应商接口和模型费用在部署前按实际配置确认。

## 6　逐阶段验收清单

采用独立保存的测试输入、预期输出及实际结果。以下数量与阈值用于作品验收；小样本通过率不能推断所有金融材料的表现。

### 阶段 1　持仓导入与风险

- [x] 参考组合的估值、集中度阈值边界、压力损失、纯现金、重复代码和历史风险计算通过自动化测试，当前共 7 项。
- [x] 前端通过类型检查和构建，接口已验证模板、场景修改和非法输入。
- [ ] 在浏览器完成上传、改阈值、改跌幅和非法 CSV 回退四个操作；在运行中的 Docker 引擎按 README 启动并重复参考组合检查。留存截图与命令结果。

### 阶段 2　金融文档及原文引用

- [ ] 冻结一组人工标注材料，建议 10 份，覆盖 PDF、纯文本、表格与扫描页；包含一份字段缺失或无法可靠读取的文件。
- [ ] 每条已输出的公司、日期、关键数值与单位均可回到原文位置。抽查至少 20 个可读字段，正确至少 18 个；所有已发布的数值引用均须能定位并支持相应陈述。无法确认的字段显示“待核实”。
- [ ] 同一公司不同季度的材料按发布时间区分。以 10 个预设检索问题验证混合检索和重排序，至少 8 个问题的前五个片段包含人工标注证据。保存检索结果和失败案例。

### 阶段 3　Agent 分析与真实数据接入

- [ ] 用同一个组合分别运行样例读取器和真实行情读取器；通过第 2 节的三标的、三交易日核对，报告清楚显示持仓来源、行情来源和截至时间。
- [ ] 用相关公告、无关公告、证据冲突和行情缺失各运行一次。相关公告须列出受影响代码及对应权重；无关公告不产生对应资产提醒；冲突时补查或明确待核实；缺价时暂停受影响计算。
- [ ] 保存一次完整调用轨迹和一次中断恢复记录。对报告中的组合市值、行业权重和压力损失，用同一快照独立复算，金额误差不超过 0.01 美元，权重误差不超过 0.01 个百分点。

### 阶段 4　市场方向预测

- [ ] 冻结 ETF、交易日历、数据版本和价格口径。目标是在第 t 日收盘数据可用后，估计其后五个交易日收益大于零的概率。训练标签、概率与评价指标采用同一收益口径。
- [ ] 按时间滚动训练和评估，至少保留三个互不重叠的测试窗口。删除训练集中标签结束日进入下一验证或测试期的样本；特征、校准器只使用预测时已可获得的数据。公告按公开时间对齐。
- [ ] 同表报告各窗口样本量、方向准确率、概率 Brier 分数与校准图。先与训练期历史上涨频率比较；动量规则可单独比较方向准确率。保存逐日预测文件和失败分析。若样本外概率表现未优于基线，交付实验结果，展示版保留基线或标记研究模式。
- [ ] 上线时开始保存带时间戳的预测，五个交易日后才能结算。阶段验收看可复现回测，持续前瞻表现另行积累。

### 阶段 5　持续监控与站内提醒

- [ ] 用固定快照依次回放“未越线、刚好等于阈值、首次越线、重复输入、过期数据”；实际提醒数分别符合预设规则。记录触发原因、原文或价格快照、关联持仓和规则版本。
- [ ] 对同一用户、组合、规则及事件重复投递任务三次，只生成一条提醒。验证冷却期、退出再越线、取消订阅、失败重试和送达记录。
- [ ] 在一个实际交易日的供应商数据可用后，观察一次完整后台任务。保留调度时间、来源更新时间、抓取结果和提醒状态；网页关闭时任务仍可完成。

### 阶段 6　安全与公网演示

- [ ] 用两个演示账户验证 API、数据库和文件访问隔离。账户 A 只能读取自己的持仓、报告、任务和原始文件；服务密钥只存在于服务端。
- [ ] 上传含有索取持仓或要求发送消息文字的测试文档。文档文本仅作为证据；工具调用仍受账户权限和订阅规则约束。记录拦截结果及实际调用。
- [ ] 从公网链接走完整流程，展示一条真实公告、一笔可复算的风险和一次站内提醒。重启 Worker 并复核任务恢复，保存延迟、调用成本及备份恢复结果。
